# Sprint 1 decisions

## Expanded platform decisions — 31 October 2026

The later user request expands the original Sprint 1 limit. New work is on `feature/luxury-venue-platform` from the complete local implementation. Earlier Sprint 1 scope statements below remain historical delivery records.

18. The saved HTML supplied by the user is the visual source after online canvas access was declined. See `DESIGN_REFERENCE.md` for its internal conflicts. Use rendered Cormorant Garamond/Manrope, exact requested hex tokens and four named themes; enlarge undersized sample controls to 44 px and calculate contrast instead of trusting the canvas's incorrect white-on-gold claim. The licensed Latin font assets are self-hosted.
19. Owner accounts use email/password with bcrypt cost 12, separate one-hour account tokens, and explicit owned-venue selection to issue the existing scoped staff token. Registration defaults off in the production server until email delivery/verification is implemented. An owner staff row has a random, undisclosed PIN hash, so account registration does not create a usable shared staff PIN. Existing PIN flows remain for separately provisioned staff.
20. Owner API additions are specified in `API_EXTENSIONS.md`. Draft profiles are private; public site responses whitelist fields and require publication. Go-live currently requires verified account, active menu item, active table and active/trial venue. Receiving-account verification is a later slice and must be added to launch gates before payment-enabled production launch. No endpoint marks email or payouts verified from client input. Logo/cover input is currently limited to null pending owned-asset upload integration.
21. Type presets create bilingual categories with persisted KITCHEN/BAR defaults; item creation uses the category default unless staff explicitly choose a station. Backlog US-604 requires a default table and sample menu: create one explicitly flagged sample table and an unavailable zero-priced item named Sample data. Sample entries cannot satisfy go-live checks; explicitly generating a matching table adopts it as real inventory, and editing a sample item removes its sample flag. No sample price is presented as a real venue price. Account/slug uniqueness is serialized with database advisory locks and backed by unique constraints. Disabled owner accounts revoke access to admin routes immediately.
22. Tables use a 100-row creation/import batch and 1000-table venue ceiling to bound QR export cost. Imports are atomic; duplicate labels reuse existing metadata. New/rotated QR signatures bind venue and label with a format marker while retaining the documented opaque code.signature API contract. A migration preserves legacy printed stickers until explicitly rotated. Human-readable venue/table query parameters are descriptive and never grant access.
23. Stickers keep black/white QR modules and a four-module quiet zone regardless of venue theme. Payment-provider names are omitted until an enabled provider is configured. Browser preview uses the recovered display/UI fonts; current PDF uses standard Helvetica and PNG uses system serif/sans. Exact exported font fidelity and physical-device print/scanner testing remain explicit delivery gaps.

The supplied documents are the product authority. Original Office files are preserved under their requested folders. `0001_init.sql` is byte-for-byte the supplied `03_cloud_menu_schema.sql` (its PostgreSQL 15+ header is compatible with the requested PostgreSQL 16).

1. Sprint scope: follow the detailed roadmap S1 exit criterion, ticket data visible through API. US-204 mentions KDS within 2 seconds, while US-501/502 put the full queue and state transitions in S2. S1 stores ticket snapshots and exposes a read-only staff ticket list. No split, bill, payment or ticket-state workflows are implemented.
2. Canonical future staff WebSocket URL is `/v1/ws` (endpoint overview and section 10.2). Section 3 also calls it `/v1/staff/ws`. Full staff real-time UI is S2.
3. Repricing before confirmation: add authenticated `POST /v1/sessions/:id/order-quote` returning server-priced lines and a signed, expiring quote. POST orders accepts additive `quote_token`; stale quotes yield 409 PRICE_CHANGED and create no order. Without a quote, the documented order endpoint still reprices all lines server-side. The guest always quotes and confirms a changed total before sending.
4. New admin contracts are documented in `docs/API_EXTENSIONS.md`; the source has no admin endpoint shapes. All use venue scoping and MANAGER/OWNER authorization. Soft delete preserves order history.
5. Participant name editing uses PATCH `/v1/sessions/:id/participant` for the current token's participant only. A device proof issued at first scan is needed to recover a participant token on rescan; the public random device UUID alone is not authentication. The guest persists that proof locally.
6. Guest session tokens last six hours, staff tokens one hour. Session tokens are reused while unexpired on an authenticated rescan. Secrets are supplied through environment/secret manager, never source. At most 20 participants unless the venue explicitly configures less.
7. No real venue data: all fixtures/seeds explicitly say DEMO. Example names and prices originate in backlog examples and wireframes and do not describe an operating venue. No production metrics are claimed.
8. EN/SW translations are draft engineering copy pending Product Owner/native-speaker review. Aggregator, fiscal treatment, cloud region and settlement model remain open source-document decisions.
9. Empty local repository: create a source-only main baseline, then exact requested `sprint-1` branch. Use the connected samrickie profile as the local commit author. Remote destination remains pending user input.
10. External DoD gates (peer review, merge through green CI, PO review, staging, physical device tests) cannot be self-certified. Track evidence and gaps per story in `docs/SPRINT_1_REPORT.md`.

11. Staff login accepts an optional staff_id. Venue plus PIN works without it when only one active account exists. Multiple accounts require an identifier so an incorrect PIN can lock the intended account rather than every staff member. Managers distribute identifiers during onboarding; account creation remains an operator task this sprint.

12. Per-venue PostgreSQL advisory locks serialize Sprint 1 writes, including scans, menu edits, QR rotation and order numbering. This conservative choice makes price review and joins consistent across nodes. Revisit finer locks after measuring real contention.
13. Authenticated REST ticket data follows the detailed roadmap's S1 exit criterion. SSE/WebSocket transports remain a delivery gap; pg-boss is a lifecycle boundary only. No later-sprint ticket-state or payment workflow is implemented.
14. Workbox caches only shell, venue menu and immutable image variants. Writes are never queued offline. Draft translation strings are centralized in the guest i18n module. Menu caching is venue-specific and contains no participant or payment data.
15. The order idempotency hash excludes the expiring quote credential but includes every business input. A lost-response retry can refresh its quote without becoming a different order. A confirmed success clears the browser attempt id so intentionally ordering the same cart again creates a new order.
16. The S1 benchmark is an explicitly synthetic local demo with three items and no menu photos, not a pilot deployment. Browser FCP on a cached repeat visit measures shell paint; the hardware/field device matrix and throttled repeat-menu timing remain separate gates.

24. The owner app keeps bearer tokens in memory, so a reload requires login. Public production registration remains disabled while verified email delivery is missing. The owner build has a same-origin CSP, with inline styles allowed for theme tokens and data images allowed for generated QR previews. Layouts reflow from the fixed reference boards to retain 44 px targets and text enlargement; snapshots capture the implementation at 360/1440, not an assertion of exact canvas equivalence.
